🎨 Profile Card Style Lab

CSS Workshop · individual, teacher-guided · practice — not a test

⏱ Core: 30 min Quick: 15 min Extended: 45 min Works fully offline

Ground rules
• The profile on this page is 100% fictional — invented for practice. Never add real addresses, phone numbers, or photos.
• Do not edit this HTML file. Every change you make lives in one file: css-workshop.css.
• Predictions that turn out wrong are the point of this lab — you cannot fail it. Questions are welcome at any moment.
The editing loop (you'll use it all workshop):
1. Open css-workshop.css in your editor (side by side with this page).
2. Change a value → 3. Save (Ctrl+S) → 4. Switch to the browser → 5. Refresh (F5).
If nothing seems to change: check you saved the CSS file, then refresh again.

Step 1 · Watch — Me (teacher demo)

The editing loop, live

Watch the teacher edit, save, and refresh. Nothing to type yet.
When it's done, answer out loud in one sentence: "What did the teacher just do?"

Step 2 · Try it — Us (everyone, ~1 minute)

Prove the loop works on your machine

Do: in css-workshop.css, find the .avatar rule and change its background color to any color you like. Save → refresh.

Observe: the circle with the initials changed color. ✅ You now control this card from the CSS file.

Step 3 · Mission — Us (together, guided)

Turn the name red

Bea wants her name — Bea M. Villanueva — displayed in red (#d92027). The rule for the name is the one with the comment /* EXPT A */.

Predict first: you are about to change the color in the .name rule. After you save and refresh — will the name text turn red? Say it or type it as a comment.

Do: change the .name rule's color to #d92027. Save → refresh.

Observe: What actually happened? Write what you saw.

Now hunt: your change may not have had the effect you expected. Without deleting anything, make the name red anyway. To do that you must find every rule in css-workshop.css that controls this one line of text. List them — then edit the right one.

Observe: Which rule did you have to edit before the name finally turned red?

Step 4 · Mission — Us (together, guided)

Restyle the whole card — and watch who refuses

Predict first: the card's own rule (.card) sets the text color and the font for everything inside it. Change color to #0a4c8a and font-family to Georgia, serif. Before refreshing: go through the card line by line — the name, the role line, the bio, the handle (@bea.builds), the three chips, the small footnote — and guess for each one: will it change, or stay the same?

Do: make both changes in the .card rule. Save → refresh.

Observe: Mark each line: CHANGED or NOT CHANGED. Did your guesses hold up? Look closely at the initials in the circle, too. What do all the unchanged lines have in common?

Step 5 · Your turn — You (individual)

Three size puzzles

Compare the card against the grey START BAR above it — that bar is exactly as wide as the card was when you received it. (The bar is read-only worksheet chrome; don't try to edit it.)

C1 — width. In the .card rule, change width: 360px to 460px.
Predict: bigger, smaller, or same? Save → refresh → compare to the start bar. Also watch the bio paragraph — does its line-wrapping move?

C2 — padding. Change padding: 24px to 44px. The width rule still says 460px — it did not move.
Predict: will the card's edge-to-edge size change at all? Save → refresh → compare to the start bar again. Where did the extra space appear — around the text, or beyond the blue frame?

C3 — border. Change border: 3px solid to border: 8px solid.
Predict: the width rule still says 460px. Does the card grow once more? Save → refresh → start bar.

Observe + think: Your CSS says width: 460px, yet the blue-framed card is clearly wider than 460. Where are the extra pixels hiding? Name every part you suspect — the slides will confirm it next lesson.

Extra probe if you have a minute: change margin: 16px auto to margin: 60px auto. Did the card get bigger, or did it just move?

Step 6 · Make it yours — You (individual, ~2 min)

Personalize through CSS only

Change colors, fonts, and spacing until the card looks like your design. Keep the HTML untouched — everything you do stays in css-workshop.css.
This design becomes the starting point for your own profile-card homework after the CSS lecture.

Step 7 · Reflection (together, ~2 min)

Three exit questions

Answer out loud or as comments at the bottom of your CSS file:

1. When your color change didn't show up at first — what did you find when you hunted?
2. When you changed the card's own text style, which lines followed it and which refused? What did the refusers have in common?
3. If width says one number but the card measures wider — what else is adding space?

Step 8 · Extensions — only when your teacher says go (45-minute version)

Optional missions

E1 — Hover. On a new line below the .tags li rule, type the selector .tags li:hover with empty braces { }. Predict a property worth changing when the mouse rests on a chip (peek at the lecture's navigation-bar example if you're stuck), then try it.

E2 — Gradient. In the .card rule, replace the flat background value with:
linear-gradient(to right, #ffffff, #eef4ff) — save, refresh, and describe the effect.

E3 — Measure exactly (teacher-led). The teacher opens the browser inspector to show the card's exact pixel measurements. If your class isn't on this tool yet, skip E3 without worry.
